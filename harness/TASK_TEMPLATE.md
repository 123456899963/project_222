# 开发任务卡模板

> 用途：AI 接到任何开发任务后，**先填这张卡，再动手写代码**。
> 流程依据：[DEVELOPMENT_GUIDE.md](../docs/development/DEVELOPMENT_GUIDE.md)（SDD 十阶段）。
> 填写规则：`<>` 处替换为实际内容；不涉及的项写「无」，**不允许留空**。

---

## 一、任务卡（复制下面整块填写）

```markdown
# 任务卡：<任务名称>

## 1. 分级判定
- 任务编号：<如 TASK-20261107-01，供 build-log 引用>
- 分级：A / B / C / D
- 判定理由：<是否属于 MVP 范围？是否触碰冻结规则？是否跨层/跨模块？>
- 边界确认：<新增/修改端点或字段？只改单层内部？>（新增/修改端点或对外行为 = B；改契约 = C；只改单层且行为不变 = A）

## 2. 任务目标
<一句话，必须可验证。反例："完成详情页"；正例："详情页展示茶品三维属性并支持收藏/取消收藏">

## 3. 对应 PRD 需求

- 需求条目：<功能编号 / 原文摘要>

|---|---|---|
| API_CONTRACT.md | <端点，如 `GET /teas`> | <如：参数 `category/origin/season`，成功 code=0、HTTP 200> |

## 5. 涉及的前后端模块

- [ ] <可执行的判定条件 3>

| 前端 Vitest | <文件> | `npm run test:run -- <file>` | <passed 数量> |
```

## 二、AI 接到新任务时的使用流程

1. **先填卡，后写码**：收到任务先输出本模板填好的任务卡（对话中即可，不需要新建文件；PR 场景放入 PR 描述）。A 类自检通过后直接编码；C 类必须等用户确认。
2. **先定级**：按 [DEVELOPMENT_GUIDE.md](../docs/development/DEVELOPMENT_GUIDE.md) §2.1 判定 A/B/C/D。
   - **A 类**：任务卡可简写（第 4、7 节允许 3–5 行要点），填完自检后直接编码，无需用户确认。
   - **B 类**：任务卡必须完整，另附技术方案（分层落点、异常与安全、测试策略、回滚），方案可见后才编码。
   - **C 类**：填完第 12 节「待确认事项」后**停止**，等用户明确答复再继续。
   - **D 类**：只回一句范围说明，不填卡、不开发。
3. **来源必须可引用**：第 3、4 节至少填一条可追溯来源（PRD 章节 / 端点 / S-xx / 用例 ID / 页面规范）。填不出来源就停下来问用户，不得凭经验补规则。
4. **执行中升级**：编码过程中若发现需要改契约、改表、放宽安全校验、跨层调用，立刻停下，把任务卡第 1 节改为 C 类，并在第 12 节写清影响与待确认问题。
5. **交付时回填**：完成后按第 9、10 节逐条给证据（实际命令 + 实际结果），未运行的测试写「未运行」，不得写「已通过」；同时把本卡摘要写入 [build-log.md](build-log.md)。
6. **不做超出卡片的事**：卡片第 11 节列出的非目标，一律不碰；新需求另开一张卡。
7. **C 类先 ADR**：确认前先写"提议"ADR，确认后改"已采纳"，实施后由 build-log 引用。

## 三、填写示例（A 类，仅供参考）

```markdown
# 任务卡：列表页三维筛选结果计数

## 1. 分级判定
- 任务编号：TASK-20261107-01
- 分级：A
- 判定理由：行为已由 PRD/API 契约规定，仅前端纯函数落地，不改契约与数据结构
- 边界确认：只改前端单层，端点行为不变 → A

## 2. 任务目标
列表页在茶类+产地+季节同时选中时按 AND 组合请求，并显示结果总数

## 3. 对应 PRD 需求
- PRD 章节：§4.2 茶品列表
- 需求条目：三维筛选为 AND 逻辑，结果计数随筛选更新

## 4. 参考技术文档
| 文档 | 章节 / 端点 | 关键约束 |
|---|---|---|
| API_CONTRACT.md | GET /teas | 参数名 category/origin/season，page_size 默认 12 |
| DESIGN_SYSTEM.md | 筛选标签 | 色值只用 CSS 变量 |

## 5. 涉及的前后端模块
- 前端：api/teas.ts、types/tea.ts、views/TeaListView.vue
- 后端 / 数据库 / 文档：无

## 6. 预计修改的文件
- 新增：frontend/src/utils/filter.spec.ts
- 修改：frontend/src/api/teas.ts
- 不改动：分页组件、详情页路由

## 7. 实施步骤
1. 抽出筛选参数组装纯函数 —— 验证：Vitest 用例通过
2. 列表页接入并渲染 total —— 验证：手动切换筛选条件计数变化
3. 运行 Vitest —— 验证：全部通过

## 8. 可能影响的功能
- 影响：列表页请求参数
- 不受影响：详情页、收藏、分享

## 9. 验收标准
- [ ] 三条件同选时请求参数同时携带三个字段
- [ ] 无匹配时展示空态而非报错
- [ ] total 与响应 data.total 一致

## 10. 测试要求
| 类型 | 范围 | 命令 | 预期 |
|---|---|---|---|
| 前端 Vitest | filter.spec.ts | `npm run test:run -- src/utils/filter.spec.ts` | 全部 passed |

## 11. 非目标范围
- 不做多条件 OR 逻辑、不做筛选条件记忆、不动后端查询

## 12. 风险与待确认事项
- 风险：后端参数校验口径不一致时需回查 API_CONTRACT
- 用户确认记录：不适用（A 类）
- 基线例外：无
- 待确认：无
```
