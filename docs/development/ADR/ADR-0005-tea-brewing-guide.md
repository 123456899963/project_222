## 1. 背景与问题

详情页现有「冲泡参考」只有水温、投茶量、浸泡时间三个数字，新手看完仍不知道先做什么、注水多满、第二泡要多久。用户要求把它升级为「小白也能照着做」的详细教程。

现有 `teas.water_temp / tea_amount / brew_time` 只能表达三个参数，无法承载步骤、动作要领与注意事项；`tea_tips.misconception` 仅能放一条误区，且与小贴士语义耦合。若不新增结构化存储，教程只能写成前端按茶类硬编码的通用文案，无法逐款维护，也无法让管理员修正个别茶的特殊手法。

## 2. 决策驱动因素

- 用户明确要求「每款茶单独录入」，教程内容必须可按茶品独立维护
- 步骤数量因茶类而异（绿茶 4–5 步、乌龙/黑茶 6–8 步），不能写死固定条数
- MySQL 5.7.19，可用 JSON 类型，但无有效 CHECK，长度与步数只能由 Pydantic + Service 校验
- 现有 175 款茶需要上线即有内容，不能长期显示空教程
- 五层架构与统一响应体已冻结，新增能力不得破坏既有 58 个端点的行为
- 管理后台仅允许使用 Element Plus，前台继续自研组件

## 3. 备选方案

### 方案 A：新增 1:1 表 `tea_brewing_guides`，步骤存 JSON（最终选择）

- 做法：新表保存 `intro`、`steps`（JSON 数组，元素含 `title/detail/tip`）、`caution`，`tea_id` 唯一；后台整篇 upsert
- 优点：不污染 `teas` 列表查询；一篇教程一次读写，事务简单；步骤结构灵活，3–8 步自由增删；1:1 与 `tea_tips` 模式一致
- 缺点：JSON 内部字段无法用 SQL 约束，需应用层校验；后台编辑需整篇提交
- 风险：JSON 结构写错会导致详情页渲染异常，需 Schema 严格校验并在前端做缺省兜底

### 方案 B：新增 `tea_brewing_steps` 明细表（1:N）

- 做法：每步一行，字段 `tea_id / sort_order / title / detail / tip`
- 优点：关系规范，可单步查询与排序，数据库层面可加唯一索引 `(tea_id, sort_order)`
- 缺点：一次保存需删除重建多行，事务与排序维护成本高；教程天然是整体，拆分收益低
- 风险：并发编辑时排序易错乱，后台交互复杂度明显上升

### 方案 C：直接在 `teas` 表加 `brewing_guide` 列

- 做法：`teas` 增加一个 JSON 或 TEXT 列
- 优点：改动最小，无需新表与关联查询
- 缺点：`teas` 已被列表、筛选、对比等多处查询，宽表继续加大会拖累主表；语义上教程是扩展内容，应与主数据分离
- 风险：后续若增加教程版本或审核状态，迁移代价更高

## 4. 最终选择

**选择：方案 A**

理由：

1. 直接满足「每款茶单独录入 + 步骤自由增删」，同时保持读写原子性
2. 与既有 `tea_tips` 的 1:1 扩展表模式一致，团队无需学习新范式
3. 相比方案 B 少一张表、少一套排序维护逻辑；相比方案 C 不加重主表负担，符合"扩展内容独立存储"的既有约定

配套决策：

- **存量内容**：编写幂等脚本 `seed_brewing_guides.py`，对没有教程的茶按「茶类模板 + 本茶水温/投茶量/时间」生成 6 步草稿写入，管理员后续逐款润色；脚本重复执行不覆盖已有教程
- **录入入口**：内嵌在现有茶品编辑页，提供「按茶类生成草稿」按钮，避免从空白开始
- **展示方式**：前台默认只展示速查三参数，步骤与注意事项收起，按钮「展开冲泡教程（共 N 步）」右侧带下箭头，展开后箭头翻转；折叠为 320ms 高度过渡，收起时同步逐帧滚动回展开前位置（`easeInOutCubic`），遵循系统「减少动态效果」；无教程时退回现有三格卡

## 5. 影响与后果

**正面影响**

- 新手可按步骤操作，详情页信息价值提升
- 教程可逐款维护，不受前端发版限制
- 存量 175 款茶上线即有可用草稿

**负面影响 / 需要接受的代价**

- 新增第 14 张表、1 个 Alembic 迁移、2 个管理员端点，端点总数 58 → 60
- JSON 结构校验完全依赖应用层，Schema 与测试必须同步
- 草稿内容为茶类通用手法，个别名茶仍需人工校对

## 6. 验证方式

- 后端 pytest：管理员 PUT 后 `GET /teas/{id}` 返回完整教程；非管理员返回 403/40300；步数 2 或 9、标题超长返回 400；DELETE 后恢复 `null`；重复执行草稿脚本教程数不重复
- 前端 Vitest：步骤展开/折叠、空教程回退三格卡、草稿生成纯函数
- 手工冒烟：后台编辑一款茶教程 → 前台详情页立即可见并可展开

## 7. 复审条件

- 教程需要版本历史、审核流程或多语言时
- 步骤需要富文本、图片或视频嵌入时
- 需要按茶类批量继承模板并覆盖个别字段时
