## 1. 编排原则

### 1.1 范围口径（按 ADR-0003 推荐方案二）

假设用户采纳 **方案二**（先落地 PRD 已有规格的 S4/S5 + R7，全新板块延后一期）：

| 项 | 口径 |
|---|---|
| 本次实施 | S4（图片集）、S5（详情页视频）、R7（首页滚动背景）、R8（实拍图替换） |
| 本次明确不做 | R1-R5 全新内容板块（茶具/产地/文化/品牌/知识）—— 若用户确认要做，按 hybrid 方案在本计划追加任务 |
| 涉及表变更 | `teas` 增 2 列（`video_url`/`video_duration`）+ 新增 `tea_media` 关联表 |
| 涉及 API 变更 | TeaDetail/AdminTeaDetail/AdminTeaCreate/AdminTeaUpdate 追加 3 个可选字段；新增 `GET /teas/{tea_id}/images`（图片集）、`POST /admin/media/video`（视频上传） |
| 涉及页面变更 | P1 首页 Hero（滚动背景）、P3 详情页（视频播放器 + 图片缩略图）、admin 后台（视频上传 + 图片管理） |

### 1.2 如果用户选择方案一（全新板块全做）

在上述基础上追加：

| 追加项 | 说明 |
|---|---|
| 新增 2 表 + 3 扩展表 | `content_types` + `content_items` + 可选扩展表 |
| 新增约 10 个 API 端点 | `GET/POST/PUT/DELETE /content/*` + `/admin/content/*` |
| 新增 5 个前端页面 | 各板块列表页 + 详情页 |
| admin 后台追加内容管理页 | Element Plus 允许 |
| 测试用例追加 15-20 条 | 内容 CRUD + 权限 + 软失效 |

### 1.3 三条编排约束（同 MVP）

1. **垂直切片优先**：先打通 S5（视频上传 → 详情页展示），再做 S4（图片集 → 缩略图切换），最后 R7（首页背景）。
2. **数据先行**：Alembic 迁移（X-01）先于后端端点（X-04a）先于前端页面（X-04b/X-05）。
3. **同一时刻只推一条依赖链**：默认 WIP = 1；仅 X-07（素材准备）可与后端并行。

| 分级 | 本计划中的典型任务 | 执行要求 |

## 6. 风险与假设

### 6.1 主要风险

| 编号 | 风险 | 影响 | 应对 |
|---|---|---|---|
| RX-1 | Alembic 迁移破坏现有测试（schema 变更导致 ORM 映射失效） | XG0 出口阻塞 | X-01b 强制 106 条全量回归；ORM 模型同步变更 |
| RX-2 | 视频上传依赖 ffmpeg/ffprobe（校验时长），MVP 环境未预装 | S5 功能不可用 | 若环境无 ffprobe，可暂时只做文件大小校验，时长校验延后并在 build-log 标注 |
| RX-3 | 图片集表 `tea_media` 的软失效 vs 物理删除决策未在 ADR 中明确 | admin 删除行为不确定 | ADR 采纳时补充：图片集用物理删除（图片文件同步清理），与 `operation_logs` 写删除日志对齐 |
| RX-4 | 首页背景轮播图片来源/版权问题 | 上线风险 | X-07 素材准备时明确：种子用 Unsplash 授权图并留 attribution |
| RX-5 | admin 后台扩展需要 Element Plus 更多组件（上传、拖拽排序） | 后台体积膨胀 | 只在 `/admin` 路由内按需加载，前台不受影响 |

### 6.2 已采用假设

1. ADR-0003 方案 C（hybrid）+ 方案二（先做 S4/S5/R7）被用户采纳。
2. 视频上传使用 HTML5 `<video>` + `/uploads/videos/` 目录，不引入第三方播放器。
3. 首页轮播组件自研（纯 CSS/Vue transition），不引入 Swiper/slick-carousel。
4. 种子图片先用 Unsplash 授权图，后续逐步替换实拍。
5. admin 后台允许继续使用 Element Plus（AGENTS §2 已确认）。
